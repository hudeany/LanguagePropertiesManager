Language Properties Manager Bedienungsanleitung

1. Disclaimer

Language Properties Manager ist ein Tool zur Bearbeitung von Sprachen Properties Dateien mit speziellen Funktionen die andere Standardprogramme nicht oder nicht so leicht zugänglich bieten.
Dieser Editor dient dabei ausschließlich der experimentellen Verarbeitung von Texten.
Jede Verwendung findet auf eigene Gefahr statt.
Der Entwickler übernimmt KEINERLEI GEWÄHRLEISTUNG, sowohl der korrekten Funktion, sowie für Schäden die aus der Verwendung des Programms entstehen.
Verbesserungsvorschläge oder Bughinweise bitte an: languagepropertiesmanager@soderer.de


2. Begriffsklärung

2.1 LanguagePropertiesSetPath

Der Ablagepfad einer Sammlung von Sprachdateien zu einem Languageproperty zusammen mit seinem Basisnamen wird im Folgenden LanguagePropertiesSetPath genannt.
Beispiel "C:\Project\I18N\ProjektLanguageProperty" steht als Platzhalter für alle Sprachdateien der Languageproperty:
	"C:\Project\I18N\ProjektLanguageProperty.properties",
	"C:\Project\I18N\ProjektLanguageProperty_en.properties",
	"C:\Project\I18N\ProjektLanguageProperty_*.properties"

2.2 Language Properties Set Name

Der letzte Teil eines LanguagePropertiesSetPath (im obigen Beispiel "ProjektLanguageProperty") wird im Folgenden Language Properties Set Name genannt.


3. Laden von Language Properties

3.1 Einzelnes Properties Set aus Dateien Set laden

Der Button führt zu einer Datei Auswahl, in welcher man eine der Sprachdateien eines LanguagePropertiesSetPath auswählen kann.
Alle Dateien dieses Language Properties werden gemeinsam geladen und in der Datentabelle links im Tool angezeigt

3.2 Alle verfügbaren Properties Sets aus Unterverzeichnissen laden

Der Button führt zu einer Ordner Auswahl. Es werden dann alle verfügbaren Language Properties aus allen Unterverzeichnissen dieses Ordners geladen.
Dazu wird nach Dateien mit einem der Sprachenkennzeichen "_en" oder "_de" und der Dateierweiterung ".properties" gesucht.
Für alle gefundenen LanguagePropertiesSetPath werden dann auch alle weiteren verfügbaren Sprachen geladen und in der Datentabelle links im Tool angezeigt
Je nach Anzahl der Unterverzeichnisse und Dateien und deren Größe kann dies einen Moment Zeit beanspruchen.

3.3 Excel Import

Der Button "Import aus einzelner Datei" erlaubt die Angabe einer einzelnen Excel Datei, um alle darin gespeicherten Language Properties Sets daraus zu laden.
Diese Excel Datei sollte aus einem einzelnen Sheet bestehen und kann folgende Spalten enthalten:
	"Path" oder "Pfad" (Genauer LanguagePropertiesSetPath für dieses Language Properties Set, Platzhalter ~ und $HOME sind erlaubt, optional)
	"Key" oder "Schlüssel" (Key zum Property Wert, erforderlich)
	"Index", "Idx" oder "Org.Idx" (Indizierung innerhalb eines Language Properties Sets um eine Reihenfolge der einzelnen Propertywerte einzuhalten, optional)
	"Default" (Default Sprachwert für den Key, optional)
	"en", "de", "de_AT", "de_CH", "fr", ... (Sprachwerte der einzelnen Sprachenkennzeichen, auch Länderspezifische Kennzeichen mit Unterstrich sind erlaubt)

3.4 CSV Import

Der Button "Import aus einzelner Datei" erlaubt die Angabe einer einzelnen CSV Datei, um alle darin gespeicherten Language Properties Sets daraus zu laden.
Diese CSV Datei kann folgende Spalten enthalten:
	"Path" oder "Pfad" (Genauer LanguagePropertiesSetPath für dieses Language Properties Set, Platzhalter ~ und $HOME sind erlaubt, optional)
	"Key" oder "Schlüssel" (Key zum Property Wert, erforderlich)
	"Index", "Idx" oder "Org.Idx" (Indizierung innerhalb eines Language Properties Sets um eine Reihenfolge der einzelnen Propertywerte einzuhalten, optional)
	"Default" (Default Sprachwert für den Key, optional)
	"en", "de", "de_AT", "de_CH", "fr", ... (Sprachwerte der einzelnen Sprachenkennzeichen, auch Länderspezifische Kennzeichen mit Unterstrich sind erlaubt)

3.5 Kürzlich verwendete Pfade

Geöffnete Dateipfade aus 3.1 und Verzeichnispfade aus 3.2 werden in einer Liste zur späteren schnellen Wiederverwendung gespeichert.
Diese können für späteren schnellen Zugang mittels dem Button "Kürzlich geöffnete Dateien öffnen" verwendet werden und werden dann im gleichen Modus wie zuvor geöffnet.
Der zuletzt verwendete Eintrag ist in der Auswahl vorbelegt.
Die Einträge der Liste können in der Auswahl per Drag&Drop umsortiert und mit der Entf-Taste gelöscht werden. Diese Änderungen werden auch dann übernommen, wenn die Auswahl abgebrochen wird.

3.6 Zusätzlicher Import in bestehende Properties

Alle Lade- und Import-Buttons aus 3.1 bis 3.5 ersetzen die aktuell im Tool geladenen Properties.
Der Button "Weitere Properties importieren (zum bestehenden Satz hinzufügen)" importiert dagegen zusätzliche Properties in die aktuell geladenen Properties, ohne diese zu verwerfen.
Dies ist z.B. hilfreich, um Übersetzungen eines externen Übersetzers, aus einem anderen Entwicklungszweig oder aus einem anderen Modul einzuspielen.
Der Button öffnet ein Menü zur Auswahl der Quelle:
	"Aus zuletzt verwendeten ..." (wie in 3.5)
	"Aus Properties-Datei ..." (wie in 3.1)
	"Aus Verzeichnis ..." (wie in 3.2)
	"Aus Excel-Datei ..." (wie in 3.3)
	"Aus CSV-Datei ..." (wie in 3.4)
Tritt beim Lesen der Quelle ein Fehler auf oder wird der Vorgang abgebrochen, bleiben die aktuell geladenen Properties unverändert.

Zuordnung der importierten Properties:
Ein importiertes Property wird einem bereits vorhandenen Property mit demselben Key zugeordnet, wenn dieses denselben LanguagePropertiesSetPath hat.
Gibt es keinen solchen Treffer, genügt derselbe Language Properties Set Name (z.B. bei einer Kopie des Properties Sets in einem anderen Verzeichnis). Fehlt einer Seite die Pfadangabe (z.B. bei Excel und CSV Dateien ohne Spalte "Path"), genügt der Key allein.
Passt ein Key zu mehreren geladenen Properties Sets, ist die Zuordnung nicht eindeutig. Dieser Eintrag wird dann übersprungen und im Ergebnisbericht aufgeführt.
Verglichen wird jeweils pro Key und Sprache. Ein Sprachwert gilt als neu, wenn das vorhandene Property für diese Sprache keinen Wert hat. Kommentare werden wie Sprachwerte behandelt.
Neue Keys werden, soweit eindeutig möglich, dem passenden geladenen Properties Set zugeordnet. So wird beim Speichern nicht in die Dateien der Importquelle geschrieben.
Ist das nicht möglich, behalten neue Keys den LanguagePropertiesSetPath der Importquelle und würden beim Speichern dorthin geschrieben. Darauf weist der Ergebnisbericht ausdrücklich hin.
Neu hinzukommende Sprachenkennzeichen werden für alle Properties angelegt.

Behandlung von Konflikten:
Nur wenn importierte Werte von bereits vorhandenen, nicht leeren Werten abweichen, erfolgt eine Abfrage.
Diese zeigt die Anzahl der neuen Keys, der bereits vorhandenen Keys, der Keys mit abweichenden Werten, der füllbaren leeren Werte und der übersprungenen Einträge an.
Zur Auswahl stehen:
	"Nur Neues hinzufügen" (Neue Keys werden hinzugefügt und leere Werte gefüllt, vorhandene Werte bleiben unverändert)
	"Bestehende überschreiben" (Zusätzlich werden abweichende vorhandene Werte durch die importierten Werte ersetzt)
	"Nur leere Werte füllen" (Es werden keine neuen Keys hinzugefügt, nur leere Werte vorhandener Keys werden gefüllt)
	"Abbrechen" (Es wird nichts verändert)
Gibt es keine abweichenden Werte, werden neue Keys ohne Abfrage hinzugefügt und leere Werte gefüllt.

Nach dem Import:
Alle hinzugefügten und geänderten Properties werden in der Datentabelle ausgewählt, so dass sie direkt geprüft oder z.B. übersetzt werden können (siehe 4.5).
Die Properties gelten als geändert und müssen noch gespeichert werden.
Ein Ergebnisbericht listet hinzugefügte Keys, gefüllte, überschriebene und beibehaltene abweichende Werte, nicht hinzugefügte und übersprungene Einträge sowie neue Sprachenkennzeichen auf.
Zusätzlich enthält er das Ergebnis einer Fehlerprüfung (siehe 4.9) der importierten Einträge, da die Importquelle z.B. ein anderes Encoding verwenden kann.

3.7 Abgleich mit einem Basis-Set (identische Werte entfernen)

Der Button "Mit Basis-Set abgleichen (identische Werte entfernen)" vergleicht die aktuell geladenen Properties mit einem Basis-Set und entfernt aus den geladenen Properties alle Werte, die im Basis-Set bereits identisch enthalten sind.
Übrig bleiben nur die Abweichungen vom Basis-Set. Dies ist z.B. hilfreich für kunden- oder variantenspezifische Properties Sets, die nur die Texte enthalten sollen, welche die Texte eines Basisprodukts überschreiben.
Der Button ist nur verfügbar, wenn Properties geladen sind. Er öffnet dasselbe Menü zur Auswahl der Quelle wie in 3.6. Die gewählte Quelle wird nur als Vergleichsbasis gelesen und nicht in das Tool übernommen.
Tritt beim Lesen der Quelle ein Fehler auf oder wird der Vorgang abgebrochen, bleiben die aktuell geladenen Properties unverändert.
Sind in der Datentabelle Zeilen ausgewählt, werden nur diese abgeglichen, andernfalls alle Properties.

Zuordnung und Vergleich:
Jedes geladene Property wird seinem Gegenstück im Basis-Set nach denselben Regeln wie in 3.6 zugeordnet (gleicher LanguagePropertiesSetPath, sonst gleicher Language Properties Set Name, sonst Key allein bei fehlender Pfadangabe).
Passt ein Key zu mehreren Einträgen im Basis-Set, ist die Zuordnung nicht eindeutig. Dieser Eintrag wird dann übersprungen und im Ergebnisbericht aufgeführt.
Verglichen wird jeweils pro Key und Sprache. Nur Werte, die exakt dem Wert derselben Sprache im Basis-Set entsprechen, werden entfernt.
Werte, die vom Basis-Set abweichen oder dort fehlen, bleiben erhalten. Ebenso bleiben Properties ohne Gegenstück im Basis-Set unverändert.
Kommentare werden nicht verglichen und bleiben erhalten.

Abfrage:
Vor der Änderung erfolgt eine Abfrage mit der Anzahl der geprüften Einträge, der identischen Werte, der Einträge, die danach keinen Sprachwert mehr hätten, der Einträge ohne Gegenstück im Basis-Set und der übersprungenen Einträge.
Zur Auswahl stehen:
	"Leere Einträge löschen" (Identische Werte werden entfernt. Einträge ohne verbleibenden Sprachwert werden komplett gelöscht, auch wenn sie noch einen Kommentar haben)
	"Nur Werte leeren" (Identische Werte werden entfernt, alle Einträge bleiben erhalten)
	"Abbrechen" (Es wird nichts verändert)
Werden keine identischen Werte gefunden, erfolgt lediglich ein entsprechender Hinweis ohne weitere Aktion.

Nach dem Abgleich:
Die verbleibenden, veränderten Properties werden in der Datentabelle ausgewählt. Die Properties gelten als geändert und müssen noch gespeichert werden.
Ein Ergebnisbericht listet gelöschte Einträge, entfernte identische Werte und die verbleibenden vom Basis-Set abweichenden Werte sowie übersprungene Einträge auf.
Wichtig: Damit gelöschte Keys auch aus den Dateien entfernt werden, muss beim Speichern (siehe 6.1) die Frage, ob bereits vorhandene Properties erhalten bleiben sollen, mit "Nein" beantwortet werden. Andernfalls bleiben diese Keys in den Dateien bestehen.


4. Bearbeiten von einzelnen Property Werten

4.1 Neuanlage und Veränderung bestehender Property Werten

Bei Auswahl einer Zeile der Datentabelle links im Tool wird die detailierte Aufstellung von LanguagePropertiesSetPath, Key, optionaler Kommentar und Default
sowie alle verfügbaren anderen Sprachwerte des Property im Detailbereich des Tools rechts angezeigt.
Diese können dann bis auf den LanguagePropertiesSetPath auch bearbeitet werden.
Nach einer gewünschten Änderung kann mittels Button "Ändern" der neue Zustand übernommen werden für eine spätere Speicherung des Properties Set.
Um einen neuen Key mit Sprachwerten hinzuzufügen kann der Button "Neues Property erstellen" in der zweiten Button Leiste des Tools verwendet werden.
Nach einer gewünschten Änderung kann mittels Button "Hinzufügen" dem Properties Set angefügt werden.
Ein verwerfen aller unerwünschten Änderungen mittels Button "Verwerfen" ist in beiden Fällen jederzeit möglich.
Der Button "Zur Speicher-Text Darstellung wechseln" ändert die Anzeige der Key und Sprachwerte zur technischen Codierung in JAVA Encoding.
Dies dient der Angabe von komplexen Unicode Zeichen sofern erforderlich.
Mittels Button "Zur Anzeige-Text Darstellung wechseln" kann zur normalen Anzeigedarstellung zurückgewechselt werden.

4.2 Löschen von Property Werten

Mit dem Button "Gewählte Properties löschen" oder der Entf-Taste in der Datentabelle können alle aktuell ausgewählten Zeilen der Datentabelle auf einmal gelöscht werden.
Eine Sicherheitsabfrage erfolgt dazu.

4.3 Hinzufügen von Sprachenkennzeichen

Mit dem Button "Ein neues Sprachen Kennzeichen hinzufügen" kann ein zusätzliches Sprachenkennzeichen für alle Zeilen der Datentabelle hinzugefügt werden.

4.4 Löschen von Sprachenkennzeichen

Mit dem Button "Ein bestehendes Sprachen Kennzeichen löschen" kann ein Sprachenkennzeichen komplett für alle Zeilen der Datentabelle entfernt werden.
Es folgt ein Auswahldialog zur Angabe eines der verfügbaren Sprachenkennzeichen.
Das letzte verbleibende Sprachenkennzeichen kann nicht gelöscht werden.
Alternativ ist dies auch über das Kontextmenü der Sprachspalte möglich (siehe 4.10).

4.5 Übersetzen fehlender Sprachwerte

Mit dem Button "Translate" können fehlende Sprachwerte erstellt werden, indem der Wert in einer anderen Sprache verwendet und mit Hilfe der Dienste von DeepL (https://www.deepl.com) übersetzt wird.
Dazu ist ein API Key zur Autorisierung erforderlich, der unter "https://www.deepl.com/pro-api/" erhältlich ist.
Begrenzte Testkonten sind kostenlos, erfordern jedoch eine Kreditkartenregistrierung.
Der API Key kann im Anwendungs-Konfigurationsdialog oder bei der ersten Verwendung des Buttons "Translate" eingegeben werden.
Zuerst wird die Quellsprache, danach die Zielsprache ausgewählt.
Bei Verwendung der Default Sprache muss eine Sprache ausgewählt werden, die als Standardsprache zugeordnet ist.
Wenn nur eine weitere Sprache verfügbar ist, wird diese automatisch als Zielsprache ausgewählt.
Sind in der Datentabelle Zeilen ausgewählt, werden nur diese übersetzt, andernfalls alle Properties.
Die Übersetzung läuft mit einer Fortschrittsanzeige und kann abgebrochen werden. Anschließend wird die Anzahl der erstellten Übersetzungen angezeigt.
Die Verbindung zu DeepL verwendet die in der Anwendungs-Konfiguration eingestellten Proxy Einstellungen.

4.6 Sprachwerte übertragen

Mit dem Button "Übertragen" können Sprachwerte von einem Sprachenkennzeichen in ein anderes kopiert werden, ohne sie zu übersetzen.
Dies ist z.B. hilfreich für Sprachvarianten wie "de" und "de_AT", oder um Default Werte in eine konkrete Sprache zu übernehmen.
Zuerst wird die Quellsprache, danach die Zielsprache ausgewählt. Ist nur eine weitere Sprache verfügbar, wird diese automatisch als Zielsprache verwendet.
Übertragen werden nur nicht leere Quellwerte. Vorhandene Werte der Zielsprache werden dabei überschrieben.
Sind in der Datentabelle Zeilen ausgewählt, werden nur diese bearbeitet, andernfalls alle Properties.
Anschließend wird die Anzahl der übertragenen Werte angezeigt.

4.7 Identische Sprachwerte leeren

Mit dem Button "Identische leeren" werden Werte einer Zielsprache geleert, die exakt dem Wert einer Quellsprache entsprechen.
Dies ist z.B. hilfreich, um nicht übersetzte Werte zu finden, die nur aus einer anderen Sprache kopiert wurden, oder um überflüssige Werte einer Sprachvariante zu entfernen, die ohnehin denselben Text wie die Hauptsprache haben.
Die Auswahl von Quell- und Zielsprache erfolgt wie in 4.6.
Sind in der Datentabelle Zeilen ausgewählt, werden nur diese bearbeitet, andernfalls alle Properties.
Anschließend wird die Anzahl der geleerten Werte angezeigt.

4.8 Duplikate entfernen

Mit dem Button "Doppelte Properties finden und entfernen" können Properties gefunden und bereinigt werden, die doppelt vorkommen, also denselben LanguagePropertiesSetPath und denselben Key besitzen.
Es wird jeweils das erste Vorkommen (nach ursprünglichem Index) behalten. Fehlt diesem behaltenen Eintrag ein Sprachwert oder ein Kommentar, der aber bei einem der weiteren (verworfenen) Vorkommen vorhanden ist, wird dieser Wert vor dem Entfernen automatisch übernommen.
Vor der eigentlichen Entfernung erfolgt eine Sicherheitsabfrage mit einer Übersicht der betroffenen LanguagePropertiesSetPath/Key-Kombinationen und deren Anzahl.
Werden keine Duplikate gefunden, erfolgt lediglich ein entsprechender Hinweis ohne weitere Aktion.

4.9 Fehlerprüfung

Mit dem Button "Fehlerprüfung" werden alle Properties auf typische Fehler geprüft. Dabei wird nichts verändert.
Geprüft werden Keys, Kommentare und alle Sprachwerte auf:
	Ersetzungszeichen "�" (Hinweis auf Zeichen, die beim Lesen nicht dekodiert werden konnten)
	Mojibake (falsch dekodierte Umlaute und Sonderzeichen, z.B. "Ã¤" statt "ä", typisch bei UTF-8 Dateien, die als ISO-8859-1 bzw. Windows-1252 gelesen wurden)
	Nicht aufgelöste Unicode Escapes wie "\u00e4"
	Byte Order Mark Zeichen (BOM) innerhalb von Texten
	Isolierte Unicode Surrogates
	Steuerzeichen (außer Tabulator und Zeilenumbruch)
Keys werden zusätzlich darauf geprüft, ob sie leer sind, Leerzeichen enthalten oder die unzulässigen Zeichen "=" oder ":" enthalten.
Gefundene Fehler werden in einem Bericht mit LanguagePropertiesSetPath, Key und betroffenem Feld aufgelistet. Werden keine Fehler gefunden, erfolgt lediglich ein entsprechender Hinweis.

4.10 Kontextmenü der Tabellenspalten

Ein Rechtsklick auf die Überschrift oder eine Zelle bestimmter Spalten der Datentabelle öffnet ein Kontextmenü:
	Spalte "Pfad": Entfernt die LanguagePropertiesSetPath Angabe aller Properties. Diese Properties werden beim Speichern wie neu angelegte Properties behandelt (siehe 6.1 und 6.2).
	Sprachspalten: Leert alle Werte dieser Sprache (das Sprachenkennzeichen selbst bleibt erhalten) oder löscht das Sprachenkennzeichen komplett (wie in 4.4).
	Spalte "Kommentar": Entfernt die Kommentare aller Properties.
Vor jeder dieser Aktionen erfolgt eine Sicherheitsabfrage mit der Anzahl der betroffenen Einträge.
Die Kommentarspalte wird nur angezeigt, wenn Kommentare in der Anwendungs-Konfiguration nicht ignoriert werden.

4.11 Sortieren der Datentabelle

Ein Klick auf die Überschrift einer Spalte sortiert die Datentabelle nach dieser Spalte. Ein weiterer Klick kehrt die Sortierrichtung um.
Die aktuelle Sortierspalte und Sortierrichtung werden durch ein Symbol in der Spaltenüberschrift angezeigt.
Die Sortierung nach Key oder ursprünglichem Index erfolgt jeweils innerhalb des LanguagePropertiesSetPath.
Die Spalte "Nr" zeigt immer die aktuelle Anzeigereihenfolge und ist selbst nicht sortierbar.
Die Reihenfolge der Spalten kann per Drag&Drop der Spaltenüberschriften verändert werden.


5. Suchen und Analysieren

5.1 Suche

Das Suchfeld oberhalb der Datentabelle sucht während der Eingabe ab der aktuell ausgewählten Zeile nach dem nächsten passenden Property und wählt dieses aus.
Mit den Pfeil-Buttons neben dem Suchfeld wird zum nächsten bzw. vorherigen Treffer gesprungen.
Die Checkboxen neben dem Suchfeld legen fest, wie und wo gesucht wird. Sie sind beliebig kombinierbar:
	"Aa" (Groß-/Kleinschreibung beachten)
	"Key" (Suche in den Keys)
	"Wert" (Suche in allen Sprachwerten)
	"Pfad" (Suche im LanguagePropertiesSetPath)

5.2 Statistik

Der Button "Statistik" zeigt eine Übersicht über die aktuell geladenen Properties an. Dabei wird nichts verändert.
Diese enthält:
	Anzahl der Properties, Properties Sets und Sprachenkennzeichen
	Anzahl der Properties mit Kommentar
	Anzahl der Duplikate (siehe 4.8)
	Anzahl der Properties je LanguagePropertiesSetPath
	Je Sprachenkennzeichen die Anzahl der vorhandenen und fehlenden Werte, den Füllgrad in Prozent und die durchschnittliche Textlänge
	Den längsten Sprachwert mit Sprache, LanguagePropertiesSetPath und Key

5.3 Verwendung prüfen

Mit dem Button "Verwendung prüfen" kann geprüft werden, welche Properties im Quellcode eines Projekts verwendet werden.
Dazu werden nacheinander abgefragt:
	Das zu durchsuchende Verzeichnis (inklusive aller Unterverzeichnisse)
	Ein regulärer Ausdruck für die zu durchsuchenden Dateinamen (vorbelegt mit ".*\.java")
	Das Verwendungsmuster, in dem der Platzhalter "<property>" für den Key steht (vorbelegt mit "LangResources.get("<property>"")
Die gefundenen Dateien werden als UTF-8 gelesen und nach dem Verwendungsmuster durchsucht.
Der Bericht zeigt die Anzahl der geprüften Dateien sowie der verwendeten, unbenutzten und fehlenden Properties an.
Zusätzlich werden die Properties aufgelistet, die im Quellcode verwendet werden, aber in der Default Sprache fehlen, samt der Dateien, in denen sie verwendet werden, sowie die Properties, die im Quellcode nirgends verwendet werden.
Die Angaben einer Prüfung werden gespeichert. Mit dem Button "Verwendung mit vorherigen Einstellungen prüfen" kann eine der zuletzt verwendeten Prüfungen erneut ausgeführt werden.
Diese Liste kann wie in 3.5 umsortiert und bearbeitet werden.


6. Speichern von Language Properties Sets

6.1 Dateien speichern

Sobald an den Werten eines Language Properties Änderungen vorgenommen wurden, wird der Button "Dateien speichern" verfügbar.
Sofern den Werten im Properties Set bereits ein LanguagePropertiesSetPath zugewiesen wurde, werden die Daten genau darin (zurück-)gespeichert.
Bei neu angelegten Werten und nur einem geladenen LanguagePropertiesSetPath wird dieser LanguagePropertiesSetPath als Standardpfad für neue Werte verwendet.
Bei mehreren verfügbaren LanguagePropertiesSetPath wird zur einmaligen Angabe des zu verwendenden LanguagePropertiesSetPath für alle neuen Werte aufgefordert.
Vor dem Speichern wird abgefragt, ob in den Zieldateien bereits vorhandene Properties, die nicht im Tool geladen sind, erhalten bleiben sollen.
Existieren Zielverzeichnisse noch nicht, wird angeboten, diese anzulegen.

6.2 Properties Sets in Verzeichnis speichern anhand Set Namen

Wenn alle aktuell im Tool verfügbaren Properties bereits einen eigenen LanguagePropertiesSetPath besitzen, speichert der Button "Properties Sets in Verzeichnis speichern anhand Set Namen" diese direkt an ihren bekannten Pfaden, ohne nachzufragen.
Liegen jedoch Properties ohne LanguagePropertiesSetPath vor, fordert der Button zur Angabe eines Verzeichnispfades auf. Unter diesem werden dann alle verfügbaren LanguagePropertiesSetPath gesucht.
Zusätzlich wird für diese pfadlosen Properties ein Name abgefragt (vorbelegt mit "Multiple"), unter dem sie als eigenes Language Properties Set behandelt werden.
Die im Tool aktuell verfügbaren LanguagePropertiesSetPath werden mit diesen abgeglichen und dann bei passendem Language Properties Set Namen der Pfad des gefundenen LanguagePropertiesSetPath zur Speicherung verwendet.
Dies funktioniert nur bei eindeutiger Bezeichnung der Language Properties Set Namen. Treten hierbei uneindeutige Namen auf wird der Vorgang mit einer Fehlermeldung abgebrochen.
Wird für einen im Tool aktuell verfügbaren LanguagePropertiesSetPath kein passender verfügbarer Pfad gefunden, so wird dieses Language Properties Set im gewählten Basisverzeichnis abgelegt.
Wie in 6.1 wird abgefragt, ob bereits vorhandene Properties erhalten bleiben sollen, und das Anlegen fehlender Verzeichnisse angeboten.
Abschließend werden alle gespeicherten Properties Sets aufgelistet.

6.3 Export in einzelne Excel Datei

Der Button "Export in einzelne Datei" speichert alle im Tool aktuell verfügbaren LanguagePropertiesSetPath in einer einzelnen Excel Datei.
Hierfür wird eine Excel Datei mit einem Sheet angelegt sowie folgende Spalten mit Daten:
	"Path" (Genauer LanguagePropertiesSetPath für dieses Language Properties Set, Platzhalter ~ für das Benutzerverzeichnis im System wird soweit möglich verwendet)
	"Key" (Key zum Property Wert)
	"Org.Idx" (Indizierung innerhalb eines Language Properties Sets um eine Reihenfolge der einzelnen Propertywerte einzuhalten)
	"Default" (Default Sprachwert für den Key, soweit verfügbar)
	"en", "de", "de_AT", "de_CH", "fr", ... (Sprachwerte der einzelnen Sprachenkennzeichen, auch Länderspezifische Kennzeichen mit Unterstrich sind erlaubt)
Existiert die gewählte Datei bereits, erfolgt eine Abfrage vor dem Überschreiben.

6.4 Export in einzelne CSV Datei

Der Button "Export in einzelne CSV Datei" speichert alle im Tool aktuell verfügbaren LanguagePropertiesSetPath in einer einzelnen CSV Datei.
Hierfür wird eine CSV Datei angelegt mit folgenden Spalten mit Daten:
	"Path" (Genauer LanguagePropertiesSetPath für dieses Language Properties Set, Platzhalter ~ für das Benutzerverzeichnis im System wird soweit möglich verwendet)
	"Key" (Key zum Property Wert)
	"Org.Idx" (Indizierung innerhalb eines Language Properties Sets um eine Reihenfolge der einzelnen Propertywerte einzuhalten)
	"Default" (Default Sprachwert für den Key, soweit verfügbar)
	"en", "de", "de_AT", "de_CH", "fr", ... (Sprachwerte der einzelnen Sprachenkennzeichen, auch Länderspezifische Kennzeichen mit Unterstrich sind erlaubt)
Existiert die gewählte Datei bereits, erfolgt eine Abfrage vor dem Überschreiben.

6.5 Schließen mit ungespeicherten Änderungen

Beim Schließen des Tools sowie vor dem Laden anderer Properties (3.1 bis 3.5) wird bei ungespeicherten Änderungen abgefragt, ob diese verworfen werden sollen.


7. Individuell anpassbare Konfigurationswerte

7.1 Dateiendung der Language Properties Dateien

Standardmäßig verwendet dieses Tool die Dateierweiterung ".properties" für alle Language Properties Dateien.
Um dieses Verhalten zu überschreiben, können Sie den Konfigurationswert "PropertiesFileExtension" setzen, der im Konfigurationsmenü über die Schaltfläche "Konfiguration" (Schraubenschlüsselsymbol) verfügbar ist.
Dies erlaubt die Verwendung von Dateiendungen wie "_mytext.properties", die nicht dem Language-Properties-Standard entsprechen.
Bitte beachten Sie, dass diese Änderung dauerhaft ist und sich auf jeden Lade- oder Speichervorgang in der GUI auswirkt.
