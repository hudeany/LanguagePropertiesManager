Usage:
	java -jar LanguagePropertiesManager.jar -exportToExcel <language properties file or directory path> -excelFile <output Excel file path> [-overwrite] [-propertiesFileExtension <extension>] [-v]
	or
	java -jar LanguagePropertiesManager.jar -exportToCsv <language properties file or directory path> -csvFile <output CSV file path> [-overwrite] [-propertiesFileExtension <extension>] [-v]
	or
	java -jar LanguagePropertiesManager.jar -importFromExcel <input Excel file path> [-outputDirectory <language properties output directory>] [-propertiesFileExtension <extension>] [-v]
	or
	java -jar LanguagePropertiesManager.jar -importFromCsv <input CSV file path> [-outputDirectory <language properties output directory>] [-propertiesFileExtension <extension>] [-v]
	or
	java -jar LanguagePropertiesManager.jar -compareWithExcel <language properties file or directory path> -excelFile <Excel file path> [-propertiesFileExtension <extension>] [-v]

Mandatory parameters for Excel file export
	-exportToExcel <language properties file or directory path>
	-excelFile <output Excel file path>

Optional parameters for Excel file export
	-overwrite:
		Allow overwriting the output Excel file, if it already exists
	-propertiesFileExtension <extension>:
		Do not use the default language file extension ".properties", but a differently defined customized extension like "_mytext.properties"
	-v: verbose output with progress bar

Mandatory parameters for Excel file import
	-importFromExcel <input Excel file path>

Optional parameters for Excel file import
	-outputDirectory <language properties output directory>:
		If outputDirectory is not defined, all language properties sets will be imported to the defined original file paths in the Excel file.
		In this case every entry of the Excel file must have a path.
		If outputDirectory is defined, the existing language properties sets within that directory (including subdirectories) will be detected.
		A set existing at its original file path is used directly, other sets are matched by their set name (the set name must be unique then).
		Other language properties sets without matching file paths will be stored as new language properties sets in the output directory itself.
		Entries without path are stored as a set named like the Excel file (without extension).
	-propertiesFileExtension <extension>:
		Do not use the default language file extension ".properties", but a differently defined customized extension like "_mytext.properties"
	-v: verbose output with progress bar

Keys existing in the language properties files, but not in the imported Excel file, are kept.

Mandatory parameters for comparison with an Excel file
	-compareWithExcel <language properties file or directory path>
	-excelFile <Excel file path>:
		Excel file to compare with, e.g. an exported Excel file returned by a translator

Optional parameters for comparison with an Excel file
	-propertiesFileExtension <extension>:
		Do not use the default language file extension ".properties", but a differently defined customized extension like "_mytext.properties"
	-v: verbose output with progress bar

Properties are matched by path and key (by key only, if one of both sides has no paths).
Empty and missing values count as equal. All differences are printed (added and removed keys, added, changed and removed values, changed comments), followed by a summary per language.
Nothing is written.

Global standalone parameters
	help: Show this help manual
	gui: Open a GUI (also opened when started without any parameter)
	version: Show current local version of this tool
	update: Check for online update and ask, whether an available update shall be installed. [username [password]]
